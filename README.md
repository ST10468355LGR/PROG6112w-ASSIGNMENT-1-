1. Project Overview
The MediCare Hospital Patient Admission System is a console-based Java application developed to replace the manual, paper-based patient admission process currently used at MediCare Hospital. The hospital ward in question contains exactly twenty beds, arranged in a four-by-five layout, and is managed entirely by administrative staff who previously relied on physical paper files to record patient information, assign beds, and track availability. Because this manual process is time-consuming and prone to error — particularly in relation to misplaced records and incorrect bed allocations — the hospital commissioned the development of a simple computerised system to improve efficiency and accuracy. The resulting application allows staff to register and maintain patient information, allocate and release hospital beds, view patient and bed information, and generate basic ward reports. The system was developed using Java 17, managed with Apache Maven, and tested using JUnit 5.
2. Features Implemented
The application is divided into five distinct features, each corresponding to a specific requirement of the assignment brief. Each feature is described in detail in the paragraphs that follow.
Feature 1: Patient Management
The first feature concerns the management of patient records. The system allows staff to register a new patient by capturing a unique Patient ID, first name, surname, age, gender, medical condition, and patient category. The patient category is selected from three possible values: Inpatient, Outpatient, or Emergency. Once registered, a patient record can be searched using the Patient ID, updated to reflect any changes in personal or medical details, or deleted entirely from the system (provided that no bed is currently allocated). In addition, the system supports the display of all registered patients, allowing administrative staff to view the complete patient list at any time. This feature contributes twenty marks toward the total assessment.
Feature 2: Bed Management
The second feature concerns the management of hospital beds. The ward contains exactly twenty beds, arranged in a four-by-five grid and labelled B01 through B20. Only patients classified as Inpatients are eligible for bed allocation, as Outpatients and Emergency patients do not require an overnight stay. Administrative staff can allocate an available bed to an inpatient, release a bed when a patient is discharged, display the complete ward layout, display all available beds, and display all occupied beds. The system also prevents bed allocation when no beds remain available, thereby ensuring that the ward is never over-occupied. This feature contributes twenty marks toward the total assessment.
Feature 3: Reports
The third feature concerns the generation of reports. The system is capable of producing six distinct reports: a full list of registered patients, a list of available beds, a list of occupied beds, the total number of registered patients, the total number of occupied beds, and the ward occupancy percentage. These reports provide administrative staff with a clear, real-time overview of the ward's status and support effective decision-making. This feature contributes fifteen marks toward the total assessment.
Feature 4: Patient Categories
The fourth feature concerns the classification of patients into categories. The system uses an enumeration, or enum, named PatientCategory, which contains three values: INPATIENT, OUTPATIENT, and EMERGENCY. The Inpatient class inherits from the base Patient class, meaning that it automatically acquires all the attributes and behaviours of a standard patient while also storing additional information specific to inpatients — namely, the ward number and the bed number. The Inpatient constructor uses the super() keyword to initialise the inherited attributes before setting its own, and the displayDetails() method is overridden to include the ward and bed information. This demonstrates a clear application of inheritance, encapsulation, and polymorphism, all of which are fundamental principles of object-oriented programming. This feature contributes thirty marks toward the total assessment, making it the most heavily weighted component of the assignment.
Feature 5: Unit Testing
The fifth feature concerns the verification of the system through unit testing. A dedicated test class, MediCareSystemTest, was written using JUnit 5 and contains eleven distinct test cases. These tests verify the registration of patients, the prevention of duplicate Patient IDs, the ability to search for a patient, the ability to update patient details, the ability to delete a patient, the allocation of a bed, the release of a bed, the prevention of allocating an occupied bed, the prevention of bed allocation when all beds are occupied, the sorting of patients by surname, and the sorting of patients by Patient ID. All eleven tests pass successfully, providing confidence in the correctness of the underlying logic. This feature contributes fifteen marks toward the total assessment.
3. Project Structure
The project is organised into three main packages within the source directory: com.medicare.main, com.medicare.models, and com.medicare.services. The main package contains the HospitalAdmissionSystem class, which serves as the entry point of the application and handles all menu-driven user interaction. The models package contains the Patient class (the base class for all patients), the Inpatient class (which extends Patient), and the PatientCategory enum. The services package contains the PatientManager class, which is responsible for all patient-related operations, and the BedManager class, which is responsible for all bed-related operations. A separate test directory contains the MediCareSystemTest class, which houses the JUnit tests. Finally, a pom.xml file sits at the root of the project and manages the Maven dependencies, including JUnit 5.
4. Prerequisites
To build and run this project, the following software is required: the Java Development Kit, version 17 or higher; Apache Maven, version 3.6 or higher; and Apache NetBeans IDE, or any equivalent Java integrated development environment. All three of these tools are freely available and widely used in professional Java development.
5. Build and Run Instructions
To build and run the application using NetBeans, the user should first open NetBeans and create a new project by selecting File, then New Project, then Java with Maven, and finally Java Application. The project should be named MediCareAdmissionSystem, with a Group ID of com.medicare. The provided Java files should then be placed into their corresponding packages. Once the project is set up, the user can right-click the project and select Run, or alternatively right-click the HospitalAdmissionSystem.java file and select Run File. To build and run the application from the command line, the user should navigate to the project directory and execute the command mvn clean compile, followed by mvn exec:java -Dexec.mainClass="com.medicare.main.HospitalAdmissionSystem". This will compile the project and launch the console-based menu system.
6. Running Unit Tests
To run the unit tests, the user may either execute the command mvn test from the command line or, within NetBeans, right-click the MediCareSystemTest.java file and select Test File. NetBeans will then compile both the main and test sources, run all eleven test cases, and display the results in the Test Results window. If all tests pass, the window will show eleven green checkmarks.
